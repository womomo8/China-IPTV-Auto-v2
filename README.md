China-IPTV-Auto V3

自动发现、筛选和验证 IPv4 IPTV 直播源，持续生成经过检测的 IPTV 订阅。

一、项目目标

本项目使用 GitHub Actions 自动运行，从多个来源采集直播源，经过数据整理、快速筛选和深度媒体验证，最终发布符合项目检测标准的线路。

质量优先，不追求线路数量。

采集 1000 条，最终通过 20 条，就发布 20 条；没有合格线路时，不用未验证线路凑数。

注意：云端 IPv4、FFprobe 和 FFmpeg 检测通过，只能说明线路在当前检测环境下通过相应检查，不能保证中国移动、联通或电信网络一定能够播放。

二、工作流程

V3 统一采用五阶段流程：

1. 广泛发现：从人工订阅源和公开来源采集线路。
2. 数据整理：解析、统一数据、去重、安全检查和 IPv4 准入。
3. 快速筛选：基础连接检测，淘汰明显无效线路。
4. 深度验证：使用 FFprobe 和 FFmpeg 检查媒体流、实际读取和解码。
5. 安全发布：生成临时 M3U、检查发布资格、安全更新正式订阅。

详细流程和施工要求见 "CORE_FLOW.md"。

三、自动运行

使用 GitHub Actions：

- 每天北京时间 06:00 自动运行。
- 支持手动正式运行。
- 支持手动测试运行。
- 三种模式共用一套业务流程。
- 测试运行不覆盖正式订阅。
- 只有正式任务具备必要的仓库写入权限。

四、正式订阅

正式订阅文件：

output/iptv.m3u

订阅地址：

https://raw.githubusercontent.com/womomo8/China-IPTV-Auto-v3/main/output/iptv.m3u

该文件在首次成功发布后生成。在文件尚未实际生成前，订阅地址不可用。

五、项目结构

主要程序：

文件| 用途
"main.yml"| GitHub Actions 自动调度和正式提交
"pipeline.py"| 唯一业务入口
"settings.py"| 统一运行参数和资源预算
"sources.txt"| 订阅源配置
"discovery.py"| 多来源采集
"normalize.py"| 数据整理和 IPv4 准入
"validator.py"| 快速筛选和深度验证
"publisher.py"| M3U 生成、校验和发布准备
"tests/"| 自动化测试
"output/iptv.m3u"| 正式订阅

七、项目原则

- 只发布通过既定检测标准的线路。
- 不用采集数量代替线路质量。
- 不把云端检测冒充国内网络实测。
- 不使用未经验证的运营商资格标签。
- 不建立不必要的复杂评分、数据库和历史关系系统。
- 不让单个来源或单条线路异常轻易拖垮整个流程。
- 发布失败时保护上一份有效订阅。
- 未经测试和验收，不宣称功能已经完成。

项目仍在建设中，实际完成情况以仓库代码、GitHub Actions 运行记录和测试结果为准。
