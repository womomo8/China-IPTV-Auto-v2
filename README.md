# China-IPTV-Auto-v2

一套统一的 IPTV 公开线路自动发现、采集、筛选、检测、评分、复测和安全发布系统。

## 项目施工依据

- **唯一业务流程与施工准则：** [`docs/CORE_FLOW.md`](docs/CORE_FLOW.md)
- 项目治理、施工批次和验收记录：[`docs/MASTER_PLAN.md`](docs/MASTER_PLAN.md)

任何代码、配置、数据库、测试或工作流与 `docs/CORE_FLOW.md` 冲突时，按总流程图整改，不另建第二套业务规则。

## 正式频道

正式频道总数：38个。

| 分类 | 数量 |
|---|---:|
| 央视频道 | 10 |
| 卫视频道 | 12 |
| 港澳台频道 | 5 |
| 体育频道 | 11 |
| 合计 | 38 |

唯一频道目录：`config/channels.yaml`。未经确认不得擅自增删或合并正式频道。CCTV-5和CCTV-5+是两个独立频道。

## 数据政策

- V3系统从全新数据库开始，不迁移V1/V2历史业务数据。
- 不保留旧版本迁移代码和迁移专用测试。
- 新系统运行后，所有轮次持续使用同一个数据库，保存来源池、候选、阶段状态、检测结果和发布记录。
- GitHub Actions临时运行环境通过数据库持久化机制复用同一个数据库文件；不能每轮运行都新建空库。
- 正式订阅备份属于安全回滚保护，不能当作废弃旧数据删除。

## 自动化目标流程

来源发现与采集
→ 线路标准化与38频道匹配
→ IPv4准入和无效线路过滤
→ 全来源采集完成后统一筛选并冻结最多36个频道配对
→ 基础测速3轮
→ 统一评分
→ 深度检测
→ 频道内容检查
→ 稳定性复测最多2轮
→ 网络出口身份验证
→ 发布资格审核
→ 临时订阅检查
→ 原子更新正式订阅并备份

所有阶段由唯一主流程调度，使用同一个 `run_id` 和数据库。中断恢复不得重新采集已完成来源，也不得改变已经冻结的候选名单。
