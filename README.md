# China-IPTV-Auto-v3 重大事项与项目交接记录

## 1. 文件用途

本文件用于持久记录项目中的重大事项，确保后续开发和交接不会遗失已经确认的重要决定。

以下事项必须记录：

- 项目重大方向调整。
- 关键架构决策及其原因。
- 施工顺序发生变化。
- 重要问题得到明确结论。
- 其他会影响后续开发、验收或项目交接的重大事项。

普通代码修改、日常施工进度、单次测试结果和常规运行记录不写入本文件。

具体测试证据以 GitHub Actions 运行记录及相应验收材料为准。

## 2. 已确认的项目目标

自动筛选真正符合项目验证条件的 IPv4 IPTV 直播线路，并持续生成：

output/iptv.m3u

正式订阅只包含本轮实际通过验证的线路。

没有国内真实网络环境的证据，不得宣称已经验证特定国内地区或运营商的播放能力。

## 3. 已锁定的整体架构

固定五步业务流程：

1. 广泛发现
2. 数据整理
3. 快速筛选
4. 深度验证
5. 安全发布

固定六个核心程序：

- config.py：统一配置、运行模式、参数检查和资源限制。
- models.py：统一数据结构、接口字段、错误类型和线路状态。
- security.py：唯一 IPTV 公网访问入口，负责媒体获取和资源清单。
- sources.py：来源读取、解析、规范化和去重。
- validator.py：快速筛选、深度验证编排、可信结果接收和线路状态判定。
- pipeline.py：唯一业务入口，编排五步、汇总结果和发布资格判断。

宿主机控制器由 GitHub Actions 受限步骤承担，不增加第七个业务程序。

## 4. 已确认的关键安全架构

固定深度验证链：

security.py
→ 本轮媒体暂存和资源清单
→ 宿主机校验
→ 任务专属快照
→ 一次性无网络验证容器
→ 结构化 JSON
→ 宿主机校验
→ validator.py

已确认的安全要求：

- security.py 是唯一 IPTV 公网访问入口。
- 业务执行端不得直接访问 IPTV 公网。
- 验证容器使用 --network none。
- 验证容器不访问公网、外部 DNS、安全入口或其他业务网络。
- 验证容器使用非 root 用户。
- 验证容器只读挂载当前任务媒体快照。
- 验证容器不得访问 Docker socket。
- 宿主机必须校验任务身份、资源清单、实际文件大小和 SHA-256。
- 宿主机必须校验容器返回结果的身份、结构、退出码和完整性。
- 只有通过宿主机校验的结果才能交给 validator.py。
- 每个深度验证任务使用独立的一次性容器，任务结束后销毁。

宿主机控制器、Docker 容器和 FFmpeg/FFprobe 属于运行基础设施，不是第七个业务程序。

## 5. 已确认的线路状态和发布规则

单条线路统一采用四种状态：

- PASS
- FAIL
- UNKNOWN
- NODE_ERROR

不使用线路评分。

只有本轮 PASS 线路可以进入正式订阅。

以下情况不得覆盖正式订阅：

- 零 PASS。
- 关键故障。
- 测试运行。
- 结果不完整。
- 发布检查失败。

正式订阅路径固定为：

output/iptv.m3u

不引入持久化线路数据库，不随意增加程序、配置文件或业务入口。

## 6. 已确认的运行方式

目标运行方式：

- 每天北京时间 06:00 自动正式运行。
- 支持手动正式运行。
- 支持手动测试运行。

实际是否可用，以工作流真实运行结果为准。
