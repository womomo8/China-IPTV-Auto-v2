China-IPTV-Auto V3

国内 IPv4 直播源自动发现、质量筛选、真实播放验证与安全发布系统

设计基准：2026-11-05

一、项目目标

China-IPTV-Auto V3 的最终目标不是收集最多的直播源，而是建立一套能够持续发现、自动筛选、深度验证、国内真实网络测试并安全发布的自动化系统。

核心原则：

质量优先，数量服从质量。

1. 广泛发现国内 IPTV 直播源。
2. 自动去重、标准化及 IPv4 准入。
3. 通过基础测速和质量评分快速淘汰。
4. 通过 FFprobe、频道内容、广告占位和稳定性检测。
5. 使用真实国内 IPv4 网络验证实际播放。
6. 只发布达到全部对应质量门槛的线路。
7. 自动备份、更新订阅并保留上一版。

不为了凑满 38 个频道而降低质量标准。

假设采集到 1000 条线路，最终只有 20 条真正通过国内网络验证，那么这 20 条才是有价值的结果。

二、五层自动化架构

第一层：广泛发现

- 多来源自动发现。
- 自动采集 M3U、M3U8、TXT 等支持格式。
- 频道名称标准化。
- 线路与频道配对。
- 多来源去重。
- 保留来源出处。
- IPv4 初步准入。
- 来源任务状态记录。
- 所有来源完成后统一冻结候选快照。

第二层：快速淘汰

- 协议和地址检查。
- 基础连接测试。
- 多轮测速。
- 延迟和吞吐量测量。
- 质量评分。
- 候选排序。
- 按资源预算选择深度验证对象。

硬性准入与质量评分分开，评分不能掩盖硬性不合格。

第三层：深度验证

- FFprobe 媒体流探测。
- FFmpeg 解码验证。
- 视频及音频信息检查。
- 视频帧抽样。
- 频道内容识别。
- 串台检测。
- 广告检测。
- 黑屏、无信号和占位检测。
- 连续播放和稳定性复测。

第四层：国内网络实测

- 真实国内 IPv4 出口。
- 中国移动网络测试。
- 中国联通网络测试。
- 中国电信网络测试。
- 实际出口 IP 和运营商识别。
- 首帧时间及播放时长。
- 中断次数和码流连续性。
- 记录每条线路的运营商适用范围。

未经过国内实际网络测试的线路，不得标记为国内实测合格。

第五层：安全发布

- 最终资格审核。
- 合格线路筛选。
- 频道整理。
- M3U、TXT 等订阅生成。
- 文件完整性检查。
- SHA-256 校验。
- 自动备份上一正式版本。
- 原子替换。
- 发布失败保护及回滚。
- 发布历史记录。

三、统一工程架构

V3 必须保留：

- 一个 SQLite 数据库。
- 一个主入口。
- 一套统一配置。
- 一套频道目录。
- 一条自动化主流程。
- 一套统一任务状态管理。
- 一套统一发布机制。

核心位置：

项目| 位置
唯一数据库| "data/iptv_auto.sqlite3"
唯一主入口| "iptv_auto/pipeline.py"
统一配置| "config.yaml"
频道目录| "config/channels.yaml"
总流程图| "docs/CORE_FLOW.md"
施工总计划| "docs/MASTER_PLAN.md"
自动工作流| ".github/workflows/iptv-auto.yml"
正式订阅| "output/result.m3u"

所有业务模块共享同一数据库和 "run_id"。

禁止重复建立数据库、重复调度入口和互相独立的业务流程。

四、质量原则

1. 不设必须达到的最终线路数量。
2. 不设必须填满的频道数量。
3. 不允许未验证线路进入正式发布。
4. 不允许云端测试代替国内网络实测。
5. 不允许用 DNS 解析成功代替实际 IPv4 连接验证。
6. 不允许用 FFprobe 成功代替频道正确性验证。
7. 不允许用一次临时网络失败直接永久淘汰线路。
8. 不允许下游模块读取未经本轮冻结的候选。
9. 不允许采集不完整时提前冻结候选池。
10. 不允许发布失败破坏上一版订阅。

五、数据和任务管理

所有任务统一使用 "run_id"。

数据库负责记录：

- 来源信息。
- 线路信息。
- 频道信息。
- 线路与频道配对。
- 候选快照。
- 各阶段检测结果。
- 评分和淘汰原因。
- 国内运营商实测结果。
- 发布版本和历史记录。

阶段状态必须支持：

- PASS
- FAIL
- RETRY
- PENDING
- TIMEOUT
- UNVERIFIED
- SKIPPED
- BLOCKED

必须支持断点恢复、已完成任务跳过、失败任务有限重试及资源预算控制。

六、工程施工原则

现有 V3 代码优先保留。

- 能用的保留。
- 有问题的整改。
- 重复的合并。
- 无实际用途的文件经过确认后删除。
- 不为拆分而拆分。
- 不为了追求文件数量少而删除必要功能。
- 不擅自改变已确定的业务规则。

任何代码修改必须先检查上下游依赖，再进行测试。

七、正式验收标准

项目不能仅凭代码提交成功就判定完成。

必须完成：

1. 来源发现测试。
2. 去重和 IPv4 准入测试。
3. 候选冻结测试。
4. 基础测速及评分测试。
5. FFprobe 和内容检测测试。
6. 稳定性复测测试。
7. 国内真实 IPv4 播放测试。
8. 运营商识别测试。
9. 数据库断点恢复测试。
10. 自动备份及发布回滚测试。
11. 全流程端到端测试。
12. GitHub Actions 自动运行测试。

只有通过对应测试的功能才能标记为完成。

八、最终目标

建立一个长期自动运行的 IPTV 质量筛选系统：

广泛发现 → 快速淘汰 → 深度验证 → 国内实测 → 安全发布

真正留下能够在国内网络实际播放、频道正确、稳定可靠的 IPv4 直播源。

不追求最大数量，只追求真实可用率。
